# Theme property extraction security candidate

The maintained theme and v33x theme used standalone `lodash.pick` and shallow helpers. Selecting an own `__proto__` field can change the prototype of the returned object. Filtering that result can then turn inherited attacker fields into selected theme properties. The local positive control demonstrates this output-object behavior; it does not demonstrate remote exploitability or global Object.prototype pollution.

The candidate uses maintained Lodash 4.18.1 modules in these two theme utilities. Single-element path arrays preserve the former literal-key behavior of the standalone packages: `nested.value` and `item[0]` stay literal keys rather than becoming traversal requests. The ordered picker selects only own enumerable string keys in original order. Nil filtering and complementary extraction use maintained modules too, so an unsafe field cannot re-enter through the other half of the split.

Run `yarn test:security` on Node 22 after installing the locked development dependencies. The ten tests compile and execute the real TypeScript theme utilities; only React Native Platform is replaced with a local test value. They cover both theme variants, literal keys, ordering, inherited fields, zero/false, nil filtering, symbols, frozen input and the unsafe field on selected/complementary paths. As a positive control, the same assertions against master produced eight passes and two failures at the unsafe-field cases; the candidate passes ten.

This branch does not increment or publish a package, change the native runtime or alter an application dependency. Before adoption: finish the declaration build, publish through the existing fork release process, pin the exact resulting package through application PRs, export Android/iOS and qualify the UI on physical devices. The remaining standalone Lodash helpers used elsewhere in this library are outside this focused patch.

Validation in the canonical checkout: frozen Yarn installation succeeds with lifecycle scripts disabled, the ten focused tests pass using its own locked dependencies, targeted lint has no errors (ten pre-existing warnings in the two utility files), and the new helper passes strict TypeScript 4.6 checking. The initial Bob command failed because it interpreted an ancestor Browserslist environment map as Babel targets. Explicit per-target Babel configs now use the same standalone Bob defaults and prevent that inheritance, without modifying any parent config. Both CommonJS and ES module builds succeed (611 sources each), and the ten behavioral tests also pass against generated CommonJS files. The declaration build still reports TS2769 at Input.tsx:286. A non-emitting compiler comparison of the original theme utilities and this candidate reports exactly the same single diagnostic; no unrelated Input code was changed. Full declaration build and app adoption remain open. The added direct Lodash type dependency is pinned to the already-locked 4.14.168 compatible with TypeScript 4.6; recent type declarations require a newer compiler and are not imposed here.
